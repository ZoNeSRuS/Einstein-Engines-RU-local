# План декоративного отображения навыков AWS

## Текущее состояние (папки `Content.*` / `Resources` / `AWS`)
- **Компоненты и системы**: `CharacterSkillComponent`, `RequiredSkillComponent`, общий `SharedSkillSystem` и пустые наследники `SkillSystem` на клиенте/сервере. Проверки навыков отсутствуют: `CanReachSkillLevel` и `IsSkillBlocked` всегда дают успех.
- **Прототипы навыков**: категории (`Resources/Prototypes/AWS/Skills/categories.yml`) и отдельные навыки (`Resources/Prototypes/AWS/Skills/Attributes/*.yml`) существуют; многие игровые предметы уже используют `RequiredSkill`.
- **Контейнеры**: `SkillContainer` поддерживает уровни, списки разрешённых/запрещённых значений и очки; `SkillPointController` умеет считать стоимость, но не задействован.
- **Предыстории**: `HistoryPrototype` из `Resources/Prototypes/AWS/Historical` выдаёт контейнеры. Устаревшие культуры удалены (`culture.yml`), впереди интеграция с новой системой гражданства.
- **Возрастные очки**: `AgeSkillPointsPrototype` требует целые значения; `human.yml` приведён к целочисленным коэффициентам (5/3/1 вместо 0.5/0.3/0.1).
- **Интерфейсы**: `SkillsWindow` и `SkillsBoundUserInterface` — заглушки (используют состояние AME). Отдельного редактора навыков в меню персонажа нет.
- **Локализация**: обновлены русские строки и добавлен английский комплект (`Resources/Locale/*/aws/skills/skills.ftl`).

## Цели декоративного этапа
- Сделать навыки видимыми для игроков и администраторов без влияния на геймплей.
- Подготовить данные и инфраструктуру для последующих функциональных проверок.

## Этапы работ
1. **Аудит и корректировка данных**
   - Проверить все ссылки `skills`/`blockedSkillLevels` на существующие `SkillPrototype`; удалять или заменять устаревшие значения (как с культурами → гражданству).
   - Поддерживать целочисленные `AgeSkillPoints` и документировать формулу расчёта.
   - Привести локализации, цвета и категории к единому стилю.
2. **Декоративный редактор в меню персонажа**
   - Добавить вкладку «Навыки» в меню редактирования персонажа.
   - Использовать `SkillPointController` для подсчёта стоимости и отображения оставшихся очков; изменения пока тестовые.
   - Согласовать данные редактора с выбранным гражданством/предысториями и возрастом.
   - Настроить сохранение в профиль либо явный тестовый режим.
3. **Генерация стартового контейнера навыков**
   - Формировать `SkillContainer` при создании персонажа (профиль → mind → сущность), объединяя редактор, гражданство и возраст.
   - Валидировать данные через `SkillPointController` и синхронизировать `CharacterSkillComponent` на клиент.
   - Временно предоставить административные способы выдать навыки для теста.
4. **Игровой UI**
   - Переписать `SkillsWindow`/`SkillsBoundUserInterface` под собственный `BoundUserInterfaceState`.
   - Разделить режимы просмотра (в раунде) и редактирования (из меню).
   - Добавить кнопку/верб для открытия окна навыков у игрока.
5. **Инструменты администратора**
   - Добавить верб `ПКМ → Админ → Показать навыки` с локализацией и иконкой.
   - Дублировать список навыков в VV и консольной команде; при необходимости логировать обращения.
6. **Документация и тестирование**
   - Описать сценарии проверки (Examine, меню персонажа, верб, игровой UI).
   - Зафиксировать ограничения декоративного этапа (нет влияния на геймплей, культуры заменены гражданством).
   - Добавить автоматические проверки загрузки прототипов и корректности ссылок.

## Риски и наблюдения
- До интеграции с профилями большинство персонажей будет иметь пустой контейнер — нужен временный способ заполнения.
- Переход с культур на гражданство требует актуальных данных, иначе редактор останется пустым.
- Заглушки UI нужно переписать, иначе декоративные окна не будут информативны.

## После декоративного этапа
- Подключить геймплейные проверки к ключевым системам (медицина, инженерия, безопасность и т. д.).
- Расширить `SkillPointController` для динамических изменений в раунде.
- Настроить аналитику/логирование использования навыков для мониторинга баланса.
